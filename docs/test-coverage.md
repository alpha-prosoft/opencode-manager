# Test coverage

Every feature of the platform and where it is tested:

- **Unit**: `service/test/manager_svc/**` (`cd service && clojure -M:test:unit`) and
  `web/test/unit/manager_web/**` (`cd web && clojure -M:shadow-cljs compile test`).
- **API e2e**: `service/test-e2e/manager_svc/e2e.clj` against the compose stack with the real LLM
  (`MANAGER_URL=http://localhost:8080 clojure -M:e2e`); the section and check names are printed as it runs. It
  runs the sections of `e2e_webhooks.clj` and, when Gerrit and Jenkins answer, `e2e_ci.clj` too.
- **UI IT**: Playwright tests in `web/test/it/manager_web/*_it.clj` against the same stack (`clojure -M:it`).

Namespaces are abbreviated: `sessions/core` is `manager-svc.sessions.core-test`, `session_it` is
`manager-web.session-it`. Every command and query is listed with its roles in `authorization` (a new one fails
that test until it is added), which also proves that people can't call platform-only actions and the platform
can't act as a person.

## Counts

Recounted on 2026-11-09 after the stability work; rerun the commands when tests are added.

- Unit: 479 backend tests (`grep -rho "(deftest " service/test | wc -l`), 216 UI tests (`web/test/unit`).
- API e2e: about 371 check sites in `e2e.clj`, `e2e_ci.clj` and `e2e_webhooks.clj` (some run per item); every
  section runs guarded, so an exception is one failed check ("<section> ran to its end") and the pass still
  prints its summary.
- UI IT: 33 tests in 24 namespaces (about 350 assertions), in oidc mode through Keycloak and again in login mode.

## Running the suites repeatedly

- Run the API e2e and the UI IT one after the other, never at the same time: both change bob's, erin's and
  henry's credentials, the demo team's and the tenant's Bitbucket value and the payments team's two session slots.
- An e2e pass starts by printing each acme team's tokens used today and running sessions, fails a check when
  demo's daily budget is already spent, and stops what is still running in every team. At its end (also after
  an exception) it cancels its runs, deletes the sessions and webhooks it made, abandons the Gerrit changes it
  pushed and removes the credential values it set.
- Each IT that starts sessions, sets shared credential values, adds a webhook or pushes a Gerrit change undoes
  it in a `finally` through the API (`helpers/clean-up!`), whatever step failed.
- kaocha runs the IT namespaces in random order; the first login of a pass prints the seed
  (`Test order: kaocha seed N`), `clojure -M:it --seed N` repeats it.
- What still grows on a long-lived stack: run rows, the tenants `e2e-initech` and `uitest` (one each, never
  more), and the review runs the `gerrit-review` trigger starts for changes before they are abandoned.

## Deliberately not covered end to end

- **JWT mode** (identity provider tokens from a proxy, personas 404): the compose stack runs in login or oidc mode;
  token checks, discovery/JWKS handling and the 404 fallback are unit tested (`auth`, `idp`, web `api_test`).
- **OIDC and login mode each run end to end on their own**: the stack is started with `compose.keycloak.yml` (oidc,
  discovery URL by default) and then the manager alone is restarted without it (login mode, same data). The
  single-sign-on section and `oidc_it` assert their skip in login mode; the persona and username-login checks skip
  themselves in oidc mode.
- **Helm chart**: no cluster in the test stack; `helm template` renders the chart for `auth.mode` login, jwt and
  oidc (OIDC values, client secret from an existing Secret, claims parser file and tenants file from ConfigMaps,
  operators, `httpGitHosts`) and `helm lint` passes.
- **Bitbucket and GitHub pull requests** (push, open PR, post comments): they need write access to a real
  repository; `runs/executor` and `runs/scm` cover them with fakes. The same flows run end to end against the local
  Gerrit and Jenkins of `compose.ci.yml` (`e2e_ci`, `gerrit_it`), which skip themselves when they are not up.
- **In the browser, not driven**: the pull request picker of the start dialog (its options have no el-id), the
  platform-started marker in the runs list, the blocked-tool alert of Live activity and a refused fork or
  Run again for someone lacking a required credential (the setup gate keeps them out of every page first; the
  API e2e checks the refusals).
- **Team-only sessions in the browser**: a scheduled run takes 5 minutes to appear; the API e2e checks the rule
  and the UI's text for it is unit tested.
- **Sandbox-side gateways in the browser**: nothing in the UI calls them; the API e2e probes them from inside a
  real sandbox.
- **Configuration reload** (`POST /api/admin/reload-config`): the API e2e checks that operators may and others may
  not, and that in oidc mode the provider's discovery document and keys reload; hot reload of a changed tenants
  file or claims parser file is unit tested only (the compose stack configures tenants through the environment).
